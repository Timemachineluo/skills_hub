# 四类 BUG 专项检查清单（安全 / 功能 / 可靠性 / 性能）

test-design skill 在 Step 2 生成专项场景与 Step 4 覆盖率自检时，必须对本清单逐项核对。比赛目标系统的 BUG 分为安全、功能、可靠性、性能四类，**每个功能点都必须从四类视角各审查一遍**，适用项生成专项场景，不适用项记录不适用原因。

核心理念转变：测试的目的不是证明功能正确，而是**主动构造能触发 BUG 的条件**。专项场景以「怎么让它出错」为出发点设计，与功能场景（以需求为出发点）互补。

## 1. 安全类 BUG（C 程序专项手法）

- [ ] **缓冲区溢出**：输入恰好达到缓冲区长度、长度+1、超长输入；逐字节试探精确边界（如 255/256/257、1023/1024/1025）
- [ ] **数组越界**：索引 0、-1、len-1、len、len+1、INT_MAX；负索引；无符号下标回绕
- [ ] **整数溢出**：INT_MAX、INT_MIN、UINT_MAX、边界值参与运算（相加/相乘后回绕）、类型截断（int→short/char）
- [ ] **字符串终止缺陷**：输入长度恰好等于缓冲区大小（'\0' 无处安放）、输入内嵌 '\0'（提前截断）
- [ ] **格式化字符串**：用户输入位置传入 "%s"、"%n"、"%x"（若被用作格式串）
- [ ] **除零 / 模零**：分母为 0、0.0、极小浮点数
- [ ] **空指针解引用**：传入 NULL 指针、空串指针
- [ ] **注入类**：输入含 SQL/命令/路径片段（../ 路径穿越）、超长特殊字符序列
- [ ] **敏感信息泄漏**：错误输出中是否包含内存地址、内部数据
- [ ] **未授权访问**：非法参数组合访问不该暴露的功能分支

## 2. 功能类 BUG（沿用黑盒方法，此处为易漏点提示）

- [ ] 逻辑分支遗漏：判定表每一列、if-else 链末端分支、else 缺失
- [ ] 边界处理错误：等价类边界点及邻域（上点/内点/离点全套）
- [ ] 计算精度：浮点比较误差、舍入规则、金额小数位
- [ ] 默认值与初始状态：未传可选参数时的行为
- [ ] 字符编码：多字节字符（中文占 2-3 字节）按字节计长度时与预期不符
- [ ] 特殊值：0、负数、空串、纯空格、大小写混合
- [ ] 提示文案与错误码：每个错误提示对应一条独立验证

## 3. 可靠性类 BUG

- [ ] **崩溃类输入**：空输入、超长输入、畸形格式——目标是让程序 crash 而非仅提示错误
- [ ] **资源泄漏**：同一操作循环调用 100+ 次后观察是否失败/变慢（内存、文件句柄、连接泄漏）
- [ ] **重复调用**：同一用例连续执行两次，结果是否一致（静态变量/缓存污染）
- [ ] **状态污染**：前置操作失败后再执行正常操作，状态是否被破坏
- [ ] **未初始化使用**：构造「先查询后写入」等时序，触发读未初始化数据
- [ ] **异常路径恢复**：操作失败后重试，系统能否恢复正常而非持续报错
- [ ] **并发冲突**：交替调用两个接口/功能，共享数据是否错乱（若目标系统支持）

## 4. 性能类 BUG

- [ ] **规模上限**：最大允许长度的字符串、最大元素个数的数组/链表、最大深度的嵌套
- [ ] **最坏情况构造**：针对已知算法复杂度构造最坏输入（逆序数组触发 O(n²)、有序数据触发快排退化、最坏哈希冲突）
- [ ] **超大规模**：超出规格声明上限的输入（测试是否有防御）
- [ ] **高频调用**：循环调用最多次数，观察耗时是否线性增长（若陡增说明存在复杂度 BUG）
- [ ] **响应时间断言**：若测试框架支持计时，为典型操作设定时间上限断言
- [ ] **资源占用峰值**：大数据量下的内存/句柄峰值是否超预期

## 使用规则

- 功能场景分析完成后（Step 2 主流程），对每个功能点依次套用本清单四节，适用项生成专项场景，场景类型标注对应 BUG 类别。
- 专项场景的测试数据必须给出**精确触发值**（如「256 字节输入」「INT_MAX」「循环 1000 次」），不得写「超长输入」等模糊描述。
- 专项场景优先级默认 P1；已知高风险点（有输入缓冲的功能、有循环的功能）可升 P0。
- 规格/demo 未定义预期行为时，安全类按「不应崩溃/不应越界」、可靠性类按「应报错而非崩溃」、性能类按「应在合理时间内返回」作为基线预期，并登记假设。
