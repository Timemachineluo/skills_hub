# 穷尽性审计规程（在单次 skill 调用内完成全量场景分析）

## 问题本质

单次通读规格 + 一次性生成场景，必然遗漏，原因有三个：

1. **注意力衰减**：通读时记住的细节，在生成长清单的过程中被稀释，后生成的部分只覆盖记忆中最鲜明的功能点。
2. **过早收敛**：模型默认的停止条件是「想不出更多了」，而不是「所有待覆盖项都已覆盖」——前者是感觉，后者是可核对的判据。
3. **隐藏场景需要跨维度推导**：规格字面没有的组合、时序、残留类场景，需要专门的推导动作才会浮现。

**解法不是让模型「多想」，而是机械的逐格核对**：先把所有待覆盖义务列成台账，再逐项回填，空格子就是硬缺口。

## 一、核心工具：覆盖台账

台账是一张「义务清单」，列出**所有必须被覆盖的项**，每项标注覆盖状态与对应场景编号。

**台账先于场景生成**（先列义务，再设计场景），生成过程中逐格回填，生成完成后逐格核对。

七类义务（每类独立成节）：

| 维度 | 义务项 | 覆盖状态 | 场景编号 |
|------|--------|----------|----------|
| 需求项 | 每条 REQ-xx | 已覆盖 / 不适用（原因） | TS-xxx |
| 因子水平 | 每个功能点 × 每个因子 × 每个水平 | 同上 | TS-xxx |
| 输出 | 每个输出 / 错误码 / 提示 / 副作用 | 同上 | TS-xxx |
| 功能点对 | 每对有依赖功能点的 A→B 两步序列 | 同上 | TS-xxx |
| 组合模式 | 每个状态对象 × 六种组合模式 | 同上 | TS-xxx |
| 缺陷清单项 | abnormal-checklist 与 bug-category-checklists 的每个适用项 | 同上 | TS-xxx |
| 边界点 | 每个输入域的 B-1 / B / B+1 及等价类边界 | 同上 | TS-xxx |

**规则**：空单元格（既未覆盖也未标注不适用）= 硬缺口，必须补场景。不允许留空。

## 二、六透镜强制扫描（逐轮执行，不得合并）

每一个透镜单独过一遍台账并回填。合并执行等于没执行——合并后注意力只覆盖最顺手的维度。

1. **需求透镜**：逐条 REQ 核对，每条至少 1 个场景。
2. **因子透镜**：逐功能点的逐因子逐水平核对。
3. **输出透镜**：逐输出/错误码核对，每个至少有场景触发。
4. **组合透镜**：两步序列矩阵逐格核对（适用格全生成）。
5. **缺陷透镜**：四类 BUG 清单逐项核对。
6. **边界与异常透镜**：边界点 + 异常清单逐项核对。

每轮结束时记录：本轮核对项数、发现缺口数、补充场景数。

## 三、隐藏场景猎取清单（每功能点强制比对）

规格字面之外的场景藏在以下位置。**对每个功能点逐条比对，至少列出 3 条尚未覆盖的候选场景**并逐条判定是否纳入：

1. **限定词与从句**：「当…时」「若已…」「默认值为…」「不超过」「至少」「等/其他」、括号注释——每个限定词都是一条独立规则。
2. **数量维度**：0 个、1 个、多个、上限、上限+1、批量操作。
3. **时间维度**：立即执行、延迟执行、跨周期、时间流逝、有效期到期。
4. **顺序与重复**：重复执行、乱序执行、交错执行、A→A 连续两次。
5. **状态残留**：前序操作留下的状态如何影响后续操作（解绑后残留、重新绑定的继承）。
6. **多对象并行**：两个以上设备/用户/记录同时存在时的交互。
7. **失败后继续**：某步失败后系统是否仍可用、状态是否一致、能否重试成功。
8. **权限与身份**：不同角色执行同一功能的差异、未授权访问。
9. **交叉影响**：A 功能的输出成为 B 功能的输入；A 的副作用改变 B 的前置条件。
10. **规格举例的延伸**：规格只举了 1 个例子时，同类的其他取值。

## 四、强制追加轮（配额制）

禁止「想不出就算了」。以配额强制产生候选：

- **每功能点配额**：至少列出 3 条尚未覆盖的候选场景，逐条判定「纳入 / 不适用 + 理由」。
- **全局配额**：完成六透镜后，至少再列出 10 条跨维度候选（组合、时序、残留类优先）。
- 候选判定为「不适用」是允许的，但必须写明理由——**禁止空手跳过**。

## 五、收敛判据（全部满足才可停止）

- [ ] 台账七类义务的**适用格全部回填**，空单元格清零，不适用格均有原因标注
- [ ] 已完成**至少一轮完整反向审计**：重新读取规格原文（不是凭记忆复述）逐条比对场景矩阵
- [ ] 强制追加轮已执行：每功能点 3 条候选 + 全局 10 条候选均已逐条判定
- [ ] 数量下限满足：组合场景 ≥ 单功能点场景数的 1/3；异常场景 ≥ 正常场景的 50%
- [ ] 上述均满足

**停止条件是可核对的判据，不是「感觉够了」。** 未满足判据不得进入用例展开；本规程的全部轮次在单次调用内完成，不得留待用户后续补充。

## 六、落盘与再读（对抗注意力衰减）

- 中间产物（需求项清单、功能点清单、因子表、覆盖台账、场景矩阵）**写入工作文件**。
- 每轮审计**重新读取文件**核对，而非凭记忆复述——记忆会衰减，文件不会。
- 审计发现缺口时，先回写台账再补场景，保证台账与场景矩阵始终一致。
